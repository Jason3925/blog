# MyBlog 内容规范（CONTENT_FORMAT）

> 本文档面向**写作者**与二期 **editor**，定义 `.md` 文件必须遵守的格式契约。
> 契约的实现（TS 类型 + zod schema）位于 `packages/shared`，blog 端解析失败会在开发模式给出明确报错。

---

## 1. 目录约定

```
content/
├── posts/            # 所有文章 .md 文件
│   ├── hello-world.md
│   └── my-second-post.md
└── images/           # 图片统一放这里，md 内用相对路径引用
    └── cover.png
```

- **一篇文章 = 一个 `.md` 文件**，置于 `content/posts/`。
- **图片**统一放 `content/images/`，在正文中用**相对路径**引用（见第 4 节）。
- 文件名仅作 slug 的**兜底来源**，建议使用有语义的小写英文名，如 `hello-world.md`。

---

## 2. Frontmatter 规范（v1）

每篇 md 顶部用 YAML Frontmatter 定义元数据，以 `---` 包裹：

```yaml
---
title: 文章标题 # 必填
date: 2026-08-14 # 必填，格式 YYYY-MM-DD
tags: [React, 前端] # 选填，字符串数组
description: 一句话摘要 # 选填，缺省自动截取正文
slug: my-post # 选填，缺省取文件名（不含 .md）
cover: ../images/xxx.png # 选填，二期 CDN 转链预留字段
draft: false # 选填，默认 false；true 时仅本地可见，构建排除
series: 系列名 # 选填，预留
---
```

### 字段说明

| 字段          | 必填 | 类型         | 默认值           | 说明                                 |
| ------------- | ---- | ------------ | ---------------- | ------------------------------------ |
| `title`       | ✅   | string       | —                | 文章标题，首页列表与详情页展示       |
| `date`        | ✅   | `YYYY-MM-DD` | —                | 发布日期，决定排序                   |
| `tags`        | ❌   | string[]     | `[]`             | 标签；二期由 `#` 联想写入，提交时才同步到标签表 |
| `description` | ❌   | string       | 截取正文前若干字 | 摘要，用于列表与 SEO                            |
| `slug`        | ❌   | string       | 文件名（去 .md） | 文章 URL 唯一标识                    |
| `cover`       | ❌   | string       | —                | 封面图，二期转链预留，一期可不用     |
| `draft`       | ❌   | boolean      | `false`          | 草稿标记，`true` 时构建排除          |
| `series`      | ❌   | string       | —                | 系列名，预留字段（二期文章分组使用） |

### 规则

1. **`title`、`date` 必填**，缺失或非法在开发模式直接报错。
2. **`slug` 唯一**：出现重复时，后解析的文章覆盖先解析的（依文件扫描顺序），应避免手动冲突。
3. **`date` 决定排序**：首页按 `date` **倒序**（新→旧）。
4. **`draft: true`**：本地 `dev` 可见，`build` 时被排除（为二期发布流程预演）。
5. **标签（二期）**：编辑器里用 `#` 联想；新标签**等到文章提交**才写入后端标签表，再同步进本字段。
6. **文章引用（二期）**：正文用 `@[slug]` 指向已有文章，见第 7 节。

## 4. 图片引用约定（二期关键预留）

- 图片一律放入 `content/images/`。
- 正文中使用**相对路径**引用，例如 `![封面](../images/cover.png)`。

**一期（手工写 md）**：直接放图到 `content/images/`，md 内用相对路径引用，保持现状即可。

**二期（editor 静态化）**：

1. 编辑时图片只做本地预览；**提交文章时**才上传 OSS（未保存的图不会进 Bucket）。
2. 执行**静态化命令**时，把已上传的图**下载到本地 `content/images/`**，并将 md 内的远程 URL **改写为本地相对路径**。
3. 最终 blog 端构建产出的是**自包含静态资源**，图片跟着仓库走，**永不过期**，不依赖 OSS/CDN 可用性或签名时效。

OSS 凭证放根目录 `.env`，变量名见 `.env.example` 与 [`ARCHITECTURE.md`](./ARCHITECTURE.md) 第 4.5 节。

| 标题 / 段落 / 引用       | ✅         | react-markdown   |
| 加粗 / 斜体 / 行内代码   | ✅         | react-markdown   |

## 6. 校验与报错

- 所有 frontmatter 由 `packages/shared` 的 zod schema 校验。
- 非法文章的**处理策略（一期默认）**：
  - `title` / `date` 缺失或类型错误 → 开发模式控制台报错，该文章从列表**跳过**。
  - 可选字段类型错误（如 `tags` 不是数组）→ 开发模式警告，尽量容错。

> 二期 editor 在生成 md 时复用同一 schema，从源头避免非法内容。

## 7. 编辑器正文约定（二期）

编辑器是**一篇 Markdown**。新建时的模板：

```markdown
# 标题

2026-08-14

#

---

```

`---` 以上是元数据（标题 / 日期 / 标签），以下是正文。slug（URL 路径）由标题自动生成，界面不展示。

### 7.1 快捷输入与 Markdown 冲突

| 输入 | 行为 | 如何避免和 Markdown 打架 |
| ---- | ---- | ------------------------ |
| `#标签` | 联想已有标签；选中后插入 `#生活` | **`#` 后面跟空格**（`# 标题`）或连续 `##` 视为标题，不弹标签 |
| `@` | 联想已有文章，插入 `@[slug]` | 邮箱（字母紧贴 `@`）不触发；代码块内不触发 |
| `/` | 命令菜单：插入日期、上传图片 | 只在行首或空白后触发，避免碰到 `https://` |
| 粘贴 / 上传图片 | 先本地预览，**提交文章时**才上传 OSS | — |

标签仍是**提交文章时**才写入标签表。

### 7.2 文章引用 `@`

在正文插入指向另一篇文章的引用：

```markdown
可以对照 @[hello-world] 里的例子。
```

| 约定 | 说明 |
| ---- | ---- |
| 编辑器 | 输入 `@` 联想已有文章（标题 / slug），选中后插入 `@[slug]` |
| 落盘 | `@[hello-world]` |
| 渲染 | 链接到 `/posts/hello-world`，锚文本为该文当前标题 |
| 失效 | slug 找不到时显示为纯文本，不报错中断 |

一期手写 md 仍可用普通链接 `[标题](/posts/slug)`，效果等价。
